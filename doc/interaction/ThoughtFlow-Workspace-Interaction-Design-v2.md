本机预览：<http://127.0.0.1:8072/ThoughtFlow-Workspace-Interaction-Prototype-v2.html#/overview>。

如需重开预览服务，在仓库根目录运行：


原型中的对话、生成、配置保存、审批和恢复均为演示；选择只存于页面内存，刷新后重置。Markdown 导入可以读取主动选择的本地文件并在原型内显示全文，不上传文件。示例下载是真实下载的演示文件，不是正式交付包或可恢复备份。

原型路由用来展示交互，不直接构成最终 API／URL 合同；实施时保留现有产品深链接和必要的兼容跳转。

建议先确认：

1. 四个主入口及搜索／成文／管理的组合方式。

3. 对话归档直接进入自动处理，结果进入统一笔记与成果集阅读。
4. 专题首页展示内容，高级规则、目录及恢复作为管理操作。

## 2. 设计范围与现状差距

用户验证入口为 `http://127.0.0.1:8060/#/overview`。该入口仍显示旧总览与公共框架；仅在笔记页接入成果集卡片，不足以兑现统一交互。

此外，读取真实工作区时已定位一个清单入口兼容缺陷：普通中文专题 ID 被误送入更窄的成果集 ID 校验，导致新内容清单整体返回错误。这是后续实现必须处理的代码问题，不能用改文案或静态截图掩盖。该问题与“总览没有按新设计调整”分别记录。

本轮交付设计和原型。此前已有产品改动保留待核对；不因本原型完成而宣称产品已按 v2 实施，也不自动提交、重启或迁移真实工作区。

## 3. 统一信息架构

### 3.1 入口组合

| 层级 | 入口 | 用户目的 | 合并与调整 |
| --- | --- | --- | --- |
| 主导航 | 总览 | 继续上次工作、发现近期成果 | 保留 `#/overview`；运行状态看板转为次级管理 |
| 主导航 | 对话 | 讨论设计、补充上下文、直接归档 | 沿用 Capture 能力，面向用户称“对话”；不新增独立“生成整套”流程 |
| 主导航 | 笔记 | 浏览独立 Thought 和多文件成果集 | 聚合卡片、平铺、导入、阅读与来源选择统一入口 |
| 主导航 | 专题 | 持续组织相关成果和补充材料 | 整套内容、独立文档、参考资料分别展示 |
| 顶部全局入口 | 搜索 | 跨内容定位 | 从原独立主导航移入顶部，仍有独立结果页和可恢复 URL |
| 内容创建／来源操作 | 基于来源成文 | 把选定材料写成新独立文档 | 从笔记、成员或搜索结果进入；不再与笔记并列为主导航 |
| 侧栏底部 | 设置与管理 | 配置服务、同步、规则、任务、备份 | 聚合现有分散的管理功能；页内按管理对象分类 |
| 侧栏底部 | 使用帮助 | 理解流程、能力边界和版本 | 原“关于”中的教学及版本说明放到这里；模板维护归设置 |

“新建”按目的分开：从对话创建、导入 Markdown、基于来源成文。独立笔记的直接编辑／保存保留为次级快捷方式，不把对话归档和导入都改成模板向导。

### 3.2 不改变对象含义

- **独立 Thought**：一篇可阅读、搜索、编辑或引用的文档。
- **成果集**：稳定身份下的一套内容，拥有固定成员、目录、来源与版本。
- **专题**：组织关系及版本引用策略，不承担另一套生成发布协议。
- **后台任务**：某次执行尝试；失败不会使已经保存的内容消失。
- **来源**：原始对话、固定文档或外部材料，不默认混入正文篇数。

这些区分贯穿总览、搜索、对话结果和阅读页；不按相似标题或相同 Profile 猜测成果集关系。

### 3.3 公共框架

统一采用 v1 原型的浅灰背景、白色内容面板、蓝色主操作、轻边框与适度留白。主导航、面包屑、搜索和设置在所有页面保持同一位置与命名。

顶部展示当前位置和搜索。工作区、模型、向量、Git、索引状态放在管理区；确实影响当前操作的问题才在该操作旁提示，避免每个页面首屏都是技术状态徽标。

桌面保留侧栏；移动端使用可关闭的导航抽屉。每页只强调一个与当前目的最相关的主操作。阅读页面以正文和定位为中心，采集页面以对话为中心。

根据后续验证补充公共框架细节：侧栏依次为品牌、工作空间主导航、最近阅读、设置与帮助、本地工作区身份。按最新确认，移除左上“个人知识工作区 / local”标识卡片，移动导航同步移除。“最近阅读”来自成功打开的实际内容，成果集保留固定版本和成员；浏览器按工作区保存少量标题和内部链接，不保存正文或对话。无记录时显示空态，不填充示例数据。移动抽屉包含相同分区，关闭后还原导航按钮焦点。

主内容区使用全部剩余宽度，取消总览 1240px、公共容器 1800px 以及笔记／成果阅读面板的固定居中上限；按视口保留适量边距。总览和清单卡片随可用宽度自动分列，辅助栏在桌面保持 240–340px，平板及手机重新排列。设置面板也使用分类导航后的剩余宽度。此项以最新用户验证要求为准，替代静态原型中固定最大宽度的示例实现；对话气泡仍按内容长短自然展开，表格及代码在自身区域滚动。


## 4. 总览：继续工作与近期成果

页面顺序：

1. 标题、工作流说明；主操作“开始对话”，次操作“浏览全部内容”。
2. 内容总览、成果集、独立文档、草稿成果集统计，口径与笔记一致。
3. 最近成果：复用笔记卡片的业务标题、固定版本、内容状态与失败更新提示。
4. 继续对话：最近会话及是否存在归档结果，直接恢复对应会话。
5. 需要关注：未决设计选择、失败任务等，分别通向已有内容或任务详情。
6. 工作区健康与后台活动折叠区，进入设置管理。

不让总览成为必须先读说明、检查所有模型状态才能工作的页面。首次使用没有内容时，显示“开始对话／导入 Markdown”两条可执行路径，不能用模拟数量填充真实统计。

加载失败时保留其他已加载区块；内容清单失败必须显示错误和重试，不能回退成看起来正常的旧笔记列表。统计以服务端完整清单为准，不能从当前分页拼出全局数值。

## 5. 对话：设计与归档在同一流程内完成

### 5.1 默认页面

首屏仅显示会话名称、会话记录／新对话、对话气泡和输入框。不展示会话上下文字段表、归档预览面板、Profile 下拉框或“文档集工具／生成整套”按钮。

后端持续维护上下文。用户输入“归档”后，自动基于已有上下文选择匹配 Profile、补齐可提取字段并生成草稿。模型建议与用户明确需求分别记录；未决事项随设计草稿保存，不能伪造为已确认选择。

已有信息不要求再次填写；真正不能安全执行的错误才阻断生成。归档草稿的自动整理与正式定稿／实施批准分离，不能通过放松后端完整性校验伪造成功。

### 5.2 归档状态与结果

| 状态 | 对话内反馈 | 可操作项 |
| --- | --- | --- |
| 已接受 | 显示当前任务已创建及目标 | 等待；重复发送需由后端识别同一操作 |
| 处理中 | 气泡内显示整理范围／生成正文／校验保存阶段 | 必要时停止，避免重复点击 |
| 草稿已保存 | 业务名称、正文与来源数量、草稿未定稿说明 | 打开成果集、在笔记中查看、继续讨论 |
| 本次失败 | 保留输入，说明失败阶段；已有内容仍可读 | 重试失败项、查看详情、打开已有成果 |
| 修改冲突 | 明确未覆盖用户修改 | 核对副本与原件，选择受支持的恢复方式 |

主反馈用用户可理解的原因；request ID、模型、错误类别和原始诊断放在“失败详情／调用记录”。不把几十条内部验证规则直接堆进对话。

重试绑定新任务后，刷新或重选会话恢复新任务。新旧任务响应、无关事件、同一任务的状态反序都不能覆盖权威状态。离开页面不等同取消任务；停止也不删除已保存内容。

### 5.3 会话管理

会话记录在抽屉／对话框中筛选和选择，不与正文并列成永久侧栏。新对话显式创建新的上下文；若存在未发送输入，应提醒保留或放弃。多标签页占用只在影响当前编辑时提示，并提供已有接管流程。

## 6. 笔记与成果集：延续已确认的阅读交互

v1 已确认的聚合、概览、三栏阅读、版本选择、来源分离和副本关系继续成立。v2 补充以下入口：

- 创建区统一为“从对话创建／导入 Markdown／基于来源成文”。
- 独立文档的编辑、下载、分享、删除和加入来源放在正文操作或“更多”菜单；处理状态、路径、资源记录在次级信息区。
- 成果集成员可以加入成文来源；原始对话不默认混入整套正文来源。
- 已有定稿默认打开定稿；工作版本另有提示。版本切换检查成员存在性，不构造无效链接。
- 对话保存后总览、笔记、专题与搜索上下文一致更新；不要求用户猜测文件路径。

“笔记副本”标明来源成果集与固定版本。编辑副本不会改变归档原件；正式受管成员沿用既有编辑和并发协议，不能另建绕过访问门禁的普通编辑入口。

### 6.1 Markdown 导入

文件选择 → 导入中 → 逐文件结果 → 阅读导入 Thought。支持多文件；一个失败不抹掉其他文件的结果。保留原始文件与正文，完整保留无法导入的本地附件链接并说明附件未上传。

不要求用户把 Markdown 手工改成 Thought frontmatter。自动转换不能静默省略原文或复杂 Markdown 内容；解析不兼容时仍应能访问原始内容。不能把“转换成功”写成已经通过正式审查。

### 6.2 下载、分享、删除

| 操作 | 展示与边界 |
| --- | --- |
| 阅读下载 | 明确当前固定版本、正文／来源范围与附件边界 |
| 正式交付 | 仅在对应版本、审批等级与离线资源门禁允许时提供 |
| 备份 | 独立进入管理流程，保留恢复所需关系，不等同阅读包 |
| 分享 | 仅在工作区启用对应能力时显示；明确分享对象及链接身份 |
| 删除副本 | 核对影响与受管约束，不暗示删除了归档原件 |
| 删除专题 | 核对组织关系、快照、受管内容与进行中操作，不能一概承诺没有影响 |

## 7. 搜索：全局入口、固定内容上下文

顶部搜索和 Ctrl／⌘ + K 进入同一搜索体验。结果页保留关键词、内容类型与已有后端支持的检索方式；支持刷新、返回和深链接。列表内筛选明确只影响当前内容清单。

结果显示标题、摘要、命中位置、独立文档或“成果集 › 成员角色”、对应内容状态。需要区分命中的是可编辑笔记正文还是固定归档／快照；不能给可编辑正文摘要配上另一版本的固定链接，造成内容错配。

打开默认进入与结果身份一致的阅读目标；同时有成果集上下文时提供“查看所属成果集”。加入成文来源时固定实际读取的版本；缺失、私有候选和不可达版本不能变成普通公开结果。

空结果提供调整条件；故障提供保留条件的重试。搜索请求反序不能覆盖新查询。来源选择与“搜索成功”分别反馈，不自动开始生成新文档。

## 8. 专题：内容首页与次级管理

专题列表展示业务名称、说明、成果集与独立文档数量；支持已有筛选。创建专题先填写名称与说明，不把规则配置设为必填向导。

详情首页顺序固定为：概览 → 文档成果集 → 独立文档 → 参考资料。成果集保留自己的目录和版本；相关独立文档不被复制为成果集成员。

版本引用分别表达：跟随最新归档草稿、跟随工作版本、跟随定稿、固定版本。没有相应版本时显示不可用；不悄悄换为其他类型。更改策略需明确当前目标和版本数量；已经打开的固定阅读链接保持不变。

“管理此专题”容纳：编辑名称说明、添加／移除关联、规则与候选、参考资料目录、备份恢复、活动记录与删除。规则生成候选不代表自动批准范围；没有用户动作或既有授权的候选不静默改变整套身份。

既有 collection 的目录、分组、快照、离线交付、迁移和转换保留为相关管理操作。涉及内容归属或路径变化时显示影响范围及冲突结果；只改变主界面组织，不能删除已有能力或绕过原操作合同。

## 9. 基于来源成文：整合来源与新独立文档

从笔记创建菜单、单篇正文、成果集成员或搜索结果进入。来源在同一个来源篮里管理，不要求用户在多个页面重新选择。

流程：选择来源 → 写作目的与必要格式 → 生成预览 → 编辑／重新生成 → 保存到笔记。

- 整套添加时展开固定成员，按身份与版本去重；来源材料单独选择。
- 明确每个来源的名称、所属成果集、版本及是否可读取；移除来源不删除原件。
- 生成过程中保留来源和写作目的；失败不清空编辑内容。
- 编辑后重新生成前确认是否替换当前未保存正文，不能静默覆盖人工修改。
- 保存成功后打开新的独立 Thought，并保留来源追踪；不改变原成果集。
- 缺失来源阻断依赖它的生成并解释；不能悄悄取另一版本。

这条流程用于“基于已有材料写一篇文档”；讨论后自动归档仍在对话中完成，不要求绕行成文页。

## 10. 设置、管理与帮助

| 分区 | 包含内容 | 关键反馈 |
| --- | --- | --- |
| 通用 | 工作区信息、语言、说明偏好、可用的共享偏好 | 保存范围明确；不可写配置不伪装成可保存 |
| 模型与外部请求 | 文本／向量模型、Provider、能力、外发范围 | 连接、JSON 能力、认证、限额与临时故障分别说明 |
| 同步与版本 | Git 状态、待同步范围、现有同步控制 | 内容已保存与远端同步分别表达，冲突不吞掉 |
| 索引与后台任务 | 词法／向量索引、任务、事件、调用统计 | 明确外部调用影响；失败不遮蔽已保存内容 |
| 文档规则 | Profile、模板、版本、注册错误 | 维护入口与日常自动归档分离 |
| 备份与恢复 | 备份范围、包校验、导入、迁移及恢复记录 | 冲突前置预览、不覆盖不同字节、安全终止可查看 |
| 使用帮助 | 产品流程、状态含义、功能边界、版本说明 | 不把技术教学当作日常首屏步骤 |

原型中的模型字段用于确认分组和反馈；后续实施前核对真实配置 API，可热更新、重启生效和只读字段分别标注。敏感凭据不明文回显；能力诊断不能因 HTTP 200 就宣布归档可用。

调用统计分别表示已知缓存 token 和未知／估算项，避免把未知统计当成已证实的零命中。详细诊断保持次级，不干扰正文阅读。

## 11. 审查、定稿与交付

作为成果集或正式文档的次级管理入口，流程为：选择固定候选 → 查看检查结果与定位 → 逐项处置允许人工确认的风险 → 明确批准人／范围／等级 → 提交 → 保留审批证据。

硬错误不能普通确认绕过。正文、来源、成员或契约变化后，旧检查／处置需要重新核对。定稿失败保留工作版本和原审批状态；下载入口按实际等级可用，不借“已保存”开启正式交付。

审查页可以定位到成员及章节，返回时仍保持原选择。大任务的人工审阅范围须完整呈现，未读内容不能算已审。

### 11.1 工程移交

从适用成果集的次级管理区进入“工程移交”，与阅读下载分开。用户核对固定设计版本、开发目标、直接验收要求、模板、接收工作区及输入修订号，先生成预览再明确确认输入与对外提供范围。预览展示待决事项、阻断项、预算和成员映射；任一输入变化后旧预览与确认失效。

导出开发输入包不等于自动生成项目、运行任务或部署。相关执行应在接收端按其授权流程进行，不能因用户点过阅读下载就获得外部写入许可。

### 11.2 单篇正式文档

普通 Thought 的“转换为正式文档”保留为主动的次级操作，与自动匹配 Profile 的对话归档分开。转换前预览 Profile 版本、输入和保留原文的方式；正文编辑、检查、允许的修复、风险处置、定稿与下载共享已有文档协议。

编辑保留完整正文与来源。失败、取消或校验未通过不清空用户内容；不通过直接编辑绕过受管版本的访问或发布边界。

## 12. 共用状态、反馈与移动端

| 情况 | 统一行为 |
| --- | --- |
| 首次使用／空清单 | 显示当前无内容，提供对应创建动作 |
| 加载中 | 保留结构、说明正在读取；不闪现旧对象正文 |
| 局部读取失败 | 就地错误和重试，其他已成功区块可使用 |
| 任务失败但有旧成果 | 旧成果可读，任务失败另示 |
| 没有指定版本／来源 | 明确不可用，不替换成最新或其他来源 |
| 未保存编辑离开 | 保护输入，允许留在当前页或明确放弃 |
| 持久化冲突／人工修改 | 保留人工字节，显示影响和后续处理 |
| 多标签编辑 | 只在受影响操作上提示锁与接管 |
| 参数／能力错误 | 说明所需能力，停止无效的原样重试 |
| 暂时性网络错误 | 保留输入和目标，提供符合现有策略的重试 |
| 重复操作 | 忙碌态和后端幂等身份共同控制，不能只禁用按钮 |

移动端：顶部保留当前位置与搜索；侧栏抽屉关闭后还原焦点。阅读目录和本文章节使用独立弹窗，对话单栏、输入框不遮挡最后结果。设置分类改为可换行的紧凑导航，来源清单可滚动，表格／代码块在内容区内滚动。

所有操作有可见名称、键盘焦点和状态反馈。输入法组合期间 Enter 不发送；Shift + Enter 换行。复制失败提供可选择的完整链接；危险操作使用明确对象和影响，不能只写“确定吗”。

## 14. 原型覆盖与后续实现门禁

原型用于确认主要页面布局与路径，不能取代产品 API、并发、权限、数据保护及真实模型验证。高级功能中的配置写入、同步、恢复、审批仅显示示例步骤与边界；后端可写能力与包校验仍由实施时验证。

确认后按以下切片实施，每个切片核对真实入口，而非只截取静态示例：

| 切片 | 验收要求 |
| --- | --- |
| 公共框架＋总览 | 打开真实 `#/overview` 即见新首页；所有页面采用一致导航与视觉，不只笔记局部变化 |
| 对话归档 | 无上下文字段／整套按钮；对话归档后笔记中可发现并进入固定内容；刷新恢复权威任务 |
| 笔记与阅读 | 中文专题等真实数据不阻断清单；计数、分页、版本、成员／来源、副本一致 |
| 搜索与成文 | 结果身份正确、固定来源、去重、输入保护、独立保存及原深链接可用 |
| 专题与管理 | 内容首页、策略持久化、目录和历史功能完整可达；规则不是首屏前置步骤 |
| 设置与故障 | 只读／可写及重启边界准确；调用错误、冲突、恢复与任务状态可解释 |
| 整体回归 | 桌面／手机、刷新／前后退、空／失败状态；Go、Node、i18n、浏览器及 API／SSE 门禁 |

保留服务端访问隔离、来源完整性、人工修改保护、风险身份与审批门禁。交互重组不是放松这些要求的理由。

## 15. 建议确认路径

1. 从[总览](http://127.0.0.1:8072/ThoughtFlow-Workspace-Interaction-Prototype-v2.html#/overview)进入对话，发送“归档”，观察自动处理后打开成果集。
2. 回笔记，查看聚合／平铺、成员正文与原件／副本关系；通过“导入 Markdown”尝试一份自选文件。
3. 顶部搜索“接口”，把结果加入来源，进入成文，生成并保存新的独立笔记。
4. 在专题中添加内容，分别选择跟随归档、工作版本、定稿或固定版本；确认不适用类型时的不可用反馈。
5. 打开设置分类与帮助，检查管理入口是否更容易寻找。
6. 使用“状态示例”演示非法输出、人工修改冲突与搜索空结果；在身份服务工作版本中体验风险处置与交付门禁。
7. 缩至手机宽度，检查导航、对话输入、来源选择和固定阅读。

用户已确认上述入口组合与交互规则；产品实施及验证以单独的实施记录为准。

## 2. 数据和接口变化

除 v1 已记录的清单与专题引用 API 外，增加：

- `POST /api/content-library/sources`：接收 `thought_id`，或 `set_id`＋固定 `selection`＋可选 `member`，返回规范化来源。空成员仅展开正文，原始对话须显式选择。
- `GET /api/content-library/sources/:id`：读取已选单篇笔记的私有冻结快照，供来源预览。

普通笔记选定时读取实际 Thought 和完整结构化内容，按内容摘要保存到 `.content-registry/private/compose-sources/snapshot-<hash>.json`；后续笔记编辑不改变已选来源。该目录属于本地私有来源记录，不作为新的公开发布入口。它不是整工作区备份 API，也未增加对该临时来源篮的跨工作区备份承诺。

成果集来源使用 `document_set_member`，把套 ID、归档／正式版本、成员 key 和正文 hash 绑定到来源 ID。生成时重新读取确切可达版本并验证；客户端摘要和链接不能替代缺失正文。普通笔记来源使用 `frozen_thought`，同样校验落盘快照摘要。固定来源缺失或被篡改时，即使还有其他有效来源，也阻断本次生成，不悄悄省略。

来源篮及草稿继续由后端持久化；刷新保留来源类型、链接和固定版本元数据。生成文档的来源证据使用冻结身份。既有来源类型仍保持原兼容路径。

另修正真实清单入口的兼容缺陷：中文普通专题 ID 不符合成果集的窄 ID 合同，不能直接送到 SetHead 读取。现在仅探测合法成果集 ID，普通中文专题不再导致整个笔记／成果集清单返回错误。

## 3. 本轮回归

新增／调整的确定性回归包括：

- 普通中文专题存在时，分组、分页、固定归档和阅读包仍可读取。

## 4. 本机使用及验证边界

现有 8060 进程在本轮开始前已启动，仍持有旧的嵌入资源。新构建不会自动替换运行进程中的页面。要在 `http://127.0.0.1:8060/#/overview` 验证新交互，需要正常停止该旧进程，再在仓库目录启动新构建：

```bash
./thoughtflow -config-dir ./config/
```

同一工作区只能有一个写入进程；直接并行启动另一个实例会得到 workspace writer 冲突。本轮没有替用户终止真实服务、改配置或迁移真实工作区。

所有模型质量、真实对话归档、生产恢复和外部交付仍按原有授权及校验链路执行。本轮 API 测试使用受控夹具，不代表真实模型输出质量或生产恢复演练通过。

## 5. 对话宽度自适应补充

按后续验证反馈取消对话页的 900px 居中上限，并仅在对话页激活时取消主内容区域的 1800px 上限。页面边距与气泡区内边距按视口平滑调整；短消息保持自然宽度，长用户消息可使用 96% 对话宽度，模型回复及归档卡片可使用全部可用宽度。原有归档气泡的 48rem／56rem 限制不再限制对话页。

卡片允许在窄屏收缩；长链接可换行，代码和表格在气泡内横向滚动，图片按气泡宽度缩放。此次只调整显示样式。`make node-check`、构建和 `git diff --check` 通过；浏览器布局仍受前述环境限制，未把静态核对描述为实际多分辨率浏览器通过。

## 6. 自动专题名称补充

定位到自动成果集规划曾把 `set-<hash>` 同时写入专题 ID、slug 和 name，可读名称却放在 description。新增存储层 `CreateWithID`，分开保存服务端生成的稳定标识与展示名称，继续复用原有锁、操作幂等、创建恢复和身份冲突保护；未开放由 HTTP 创建请求任意指定内部 ID 的参数。

新专题名称优先使用显式指定的业务名称；自动归档传入通用 Profile 名称时，改从共享设计的 `project_name`、`title`、`subject`、`goal` 顺序提取，其次使用需求名称，最后才回退 Profile 名称。名称合并空白、去除控制字符，超过 60 个字符时按 Unicode 字符截短；内部 set 标识不作为自动名称。描述保存已提取的目标。同名成果集保留独立 ID，不会合并或接管其他专题；已有专题的后续规划不覆盖手工名称。此过程不额外调用模型。

已有名称恰好等于内部 set 标识的集合专题，在专题列表、详情及目录 API 返回时，从已保存且通过原有完整性检查的成果集提取可读主题；不可读取时回退已有描述。兼容只作用于展示，不改写原始专题文件、目录、ID、generation、固定成果及审批摘要；已有手工可读名称保留。真实工作区未做批量重命名。

新增回归覆盖同名不同标识、操作重放与创建恢复、身份冲突拒绝、规划重放及手工改名保护，以及旧数据三个 API 的可读标题与原始元数据字节保持一致。验证日志见 `validation/topic-title-go.log`、`validation/topic-title-node.log`；本轮 Go 全量 `make test`、Node 167／167、i18n 6／6、语法、格式、构建和空白检查通过。浏览器仍未完成独立实测。新构建须按第 4 节重启旧服务后生效。

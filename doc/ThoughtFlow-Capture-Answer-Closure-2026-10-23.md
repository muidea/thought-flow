# Capture 对话回答收口

日期：2026-10-23。后续归档事务、草稿、参数确认及最新验收结果见 [归档收口实施记录](ThoughtFlow-Capture-Archive-Closure-Implementation-2026-10-23.md)；本文下方保留此前轮次的验证结果。

## 问题与处理

“为我调研 isa95 模型”及“还有什么内容吗”的核对发现：生成协议优先维护候选文档和 Profile，服务端与前端又把 `candidate_summary` 当作聊天回答，容易只显示研究方向和拟定提纲。

新增 `assistant_reply`，明确保存当前轮完整回答。生成结果、Scratchpad 持久化、AI 消息及前端上下文快照均保留该字段；后续轮次不能沿用上一轮回答，也不能改写已经显示的回答。恢复时优先使用已持久化消息，避免重复生成对话气泡。

`candidate_summary` 用于累计归档摘要，`candidate_body` 用于累计工作材料。归档生成继续使用摘要、正文、事实和来源，不直接拼接聊天回答。内置 prompt 要求研究、解释及继续追问给出实质内容；显式要求研究计划时仍允许回答计划。缺少可选行业或受众信息不能阻止一般性解释。

OpenAI-compatible Provider 拒绝缺失或空白的 `assistant_reply`，默认 JSON 模式通过已有的上下文解析错误重试流程处理；容错补发后的无效结果直接终止。配置了 `llm.prompts.capture_context_system_path` 的自定义 prompt 也须满足此协议。没有配置对话模型时，本地规则明确说明只能整理用户输入，不能完成调研。

## 上游参数与容错模式

补充核对发现，原实现对任意 400 都移除 `response_format` 补发，掩盖了参数错误与 JSON 输出能力差异。本次改为：

- 默认要求原生 JSON 输出能力，纯文本调用不携带 `response_format`。
- 识别 `conversion_unsupported`，保留 `feature` / `unsupported_features`。在 SDK 重试循环前识别该错误，即使上游使用 5xx 或附带重试提示，也停止原样请求；业务层同样视为不可重试。
- 当时用户确认增加显式容错选项 `[llm] allow_json_fallback = true`，默认 `false`。只有错误明确且仅涉及 `response_format` 或其子功能时，移除该参数补发一次；无功能明细、普通 400 及混合其他功能均不触发降级。2026-10-24 按后续要求改为进程内记忆：同一服务地址、凭据和模型跨实例共享降级判断，避免每次重复协商；不同配置隔离，重启清空。首次并发探测协调执行，后续调用仍须逐次通过解析与业务校验。
- 补发关闭 SDK 重试，结果仍经过原有 JSON 解析及业务校验；解析或必需字段失败返回不可重试错误，阻止外层重新协商。错误信息提示 JSON 输出能力问题，日志标明发生过显式降级。
- 容错模式提高可用性，但不能提供与原生 JSON 输出相同的格式保证。仓库内没有账号刷新或账号冷却机制，本次未操作上游服务的账号管理行为。

根据 [OpenAI 官方 Structured Outputs 文档](https://developers.openai.com/api/docs/guides/structured-outputs)，`json_object` 属于 JSON mode，只保证 JSON 格式，不保证符合特定 schema；本实现始终保留业务字段校验，并未将其宣称为 `json_schema` 严格输出。第三方网关的 `conversion_unsupported` 是本次明确处理的错误协议，其 ChatGPT Web 路径能力不由 OpenAI API 文档证明。

## 验证与边界

- Go 回归通过真实 Provider 解析、可控 HTTP 模型响应、异步上下文更新及磁盘 Scratchpad，验证两轮回答、历史上下文、重读和归档材料分离。
- Node 回归验证当前轮回答、历史气泡快照及持久化消息去重。
- Chromium 回归实际提交两轮消息、等待 SSE 更新并刷新页面，确认两轮回答均保留且不显示归档元数据。
- Provider 定向 HTTP 回归覆盖默认严格、显式降级、功能不明、混合功能、普通 400、错误标记的 503、SDK 重试提示、无效 JSON、缺少回答字段及补发临时失败；验证请求次数和参数保留/移除。Capture 磁盘回归确认无效补发不写入归档上下文、不触发外层重试。
- AI、配置、Capture、Scratchpad 定向 Go race 检查通过。
- 完整检查中曾遇到专题成员 e2e 的错误判据：测试将旧关键词追加至新成员后，仍要求该关键词结果为空，未考虑新成员可合法命中。改为按已删除的 `thought_id` 检查排除，并等待异步成员更新收敛；新成员命中检查仍保留。修正后独立 API/SSE e2e 38/38 通过，未修改专题搜索生产逻辑。
- 浏览器检查还暴露了语言切换测试的启动竞态：静态 HTML 的总览 active 状态早于异步 `bind()`，测试可能在按钮绑定前点击。改为等待已有 `__thoughtflowReady` 后再交互；定向回归通过，未放宽超时或修改产品逻辑。

模型响应由测试服务固定提供；上述测试证明协议及传输、持久化、显示链路，不代表真实模型的知识准确性或回答质量评测。上下文生成没有联网检索工具，prompt 禁止声称已经检索或核验标准原文。未调用外部模型、未修改现有用户对话、未重启运行中的服务；旧对话不会因本次修改自动重写。

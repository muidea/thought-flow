## 自动归档流程修订

- 上下文提取出的非空必填字段可直接参与生成，`confirmed=false` 不再等价于缺失；不把推断字段冒充用户确认值，显式用户修改及清空仍优先。
- 模型按真实 Profile 输入契约自动填充。内置模板的用途、读者、范围等编写选择还可由后端依据会话主题/目标补齐，来源记录为 assumed；正文披露这些编写假设，不据此推断标准版本或实验结果。自定义业务必填项缺少真实内容仍会阻塞。
- 自然语言“归档”及 `/save` 一次接受生成与保存，无需先预览再确认，均走后端归档流程。Capture 不提供上下文和预览面板；字段编辑及私有草稿仅保留内部/API 能力。
- 菜单归档早于异步上下文响应时，后台先完成当前代次的类型匹配和参数提取，再生成文档；不会因为暂时没有模型结果就落成默认 note。提取结果通过代次 CAS 发布，后来的用户编辑仍受保护。
- 若独立的异步上下文响应先返回，同代次已接受的自动归档意图会转交给新的上下文任务，旧任务失效。用户修改字段或后续输入不会因此获得新的自动归档授权。已有 Thought 在没有新用户输入时直接沿用文档契约及候选正文，不要求再次抽取空上下文。
- 无来源的 research 仍生成对应类型的完整工作文档，附加未核验说明。Capture 仅将 `research_evidence_missing` 与无外部来源时的 `research_traceability` 作为归档警告，实际修订的规范验证报告保持原样；正式定稿继续失败，不能因此公开交付。
- 不安全链接、伪造的引用、章节/格式错误、真正缺少核心输入及未解决业务矛盾仍不能归档；不会为了成功改成普通 note。
- v2 模板的编写假设放入已声明的局限/待决/正文等章节，避免渲染器附加未声明的 H2 导致自动生成被自身格式校验阻塞。
- 回归从“ISA-95 调研→归档”上下文开始，经自动类型选择、字段推断、有界生成和真实磁盘保存，验证无需参数确认、来源保持为空、未核验说明持久化、重启幂等重试及正式定稿仍拒绝。浏览器另验证桌面/窄屏单次归档点击及刷新恢复。

## 自动兼容与有界故障恢复

用户进一步要求默认启用 JSON fallback 且不通过参数控制。已移除 LLM 配置字段和解析、严格模式分支及示例开关；同地址、凭据和模型共享能力记忆，明确不支持后后续调用直接兼容请求。前文提及开关、严格模式和兼容请求不重试的内容为历史记录，以下规则取代它们。

兼容请求仅对传输失败、HTTP 429/5xx 最多尝试三次。关闭该通道 SDK 重试，由单层逻辑控制可取消的退避及 Retry-After；超过 30 秒等待提示或明确禁止重试时结束。耗尽后返回终止错误，防止 Capture 外层重试扩大请求数。初始格式协商及兼容通道均不原样重试参数或鉴权错误，即使上游错误附带重试提示也不例外。

无效 JSON、字段缺失/类型错误、空候选和截断结果不触发此重试；JSON 解析与归档业务校验仍须通过。不会自动刷新账号、切换模型或重放用户归档命令。网关 502 中包含底层 403 仍保持网关故障分类，持续的上游拒绝无法由客户端重试保证恢复。

新增回归覆盖首次默认降级、缓存后 502/429 恢复、两次临时失败、耗尽预算、禁止重试提示、鉴权/参数错误、等待与取消、恢复后的内容校验，以及真实会话持久化和自动归档仅产生一个 Thought。该段的最终验收结果待下方追加。

## AetherRelay 方案对照后的最终重试策略

前节“兼容请求最多三次”的实现已被本节替代：发送后断线、一般 502、429 和读超时不足以证明上游未执行，客户端不再自动重放。聊天 SDK 重试归零；仅明确且只不支持 response_format 时协商一次兼容调用，默认启用且无配置开关。Retryable 保留后续可考虑重试的语义，AutoRetry 是独立的执行证据许可，实际 HTTP 生成通道不会单凭状态码或网关重试提示授予许可。

所有生成入口共享有限 context，能力排队、格式协商、兼容请求和业务授权的内容修复不重置预算；Classify 同样拒绝 length 截断，即使其正文是合法 JSON。语义审查/修复也走共享的自动格式协商。Capture/Refiner 原生 JSON 路径解析或业务失败不再仅因 Retryable 原样重做模型调用；本地抓取的独立恢复及显式修复能力保留。

网关错误保留 X-Request-ID、原始 code、failure_class、retryable、feature/unsupported_features，与本地 session/operation/job 关联；成功请求也记录安全 request ID。保留一般 502 与正文中的底层 403 的区别，不推断刷新账号。能力注册表最多 256 项，使用操作租约与闲置 LRU 回收，Provider 不再保留可能分裂的旧状态指针；不增加 TTL 或配置模式。

归档在生成前持久化 GenerationStarted。重启发现 preparing/interrupted/saving 且没有持久化输出或保存命令时结束未知任务，保留内容并要求显式重试；未执行任务、已准备输出和保存命令仍按各自安全路径恢复。业务通过新的归档操作或用户追问显式重试，可继续复用已确认降级的能力状态。

- 历史上下文使用的 `CaptureContextResult` 原先没有 JSON 标签，实际请求包含 `AssistantReply`、`CandidateSummary` 等 Go 字段名，与输出协议的 `assistant_reply`、`candidate_summary` 不一致。统一为 snake_case，并明确标记历史状态不是响应模板；当前轮的回答要求放在用户请求末尾。
- 自定义 Capture 系统提示词原先完全替代默认提示词，可能漏掉客户端必须消费的回答契约。默认和自定义提示词均追加必需的输出约束，要求完整的顶层 JSON 字符串字段 `assistant_reply`，回答本轮需求；摘要、工作材料和历史回答不能代替它。这些提示有助于保持协议，不能保证模型一定遵循，结果仍必须校验。
- 原解析器接受第一个语法正确的对象后才检查回答字段；前置辅助 JSON 会遮住随后有效的完整回答。Capture 改为独立解析完整候选对象，选择具有有效回答且字段类型正确的对象，不合并字段、不把对象内嵌套的示例提升为答案，也不改变其他业务入口的解析策略。
- 仅有摘要/正文、空白/null 回答、错误类型、PascalCase 键或嵌套示例仍失败并保留用户输入；不补造回答、不增加模型修复或重放请求。默认 JSON fallback、同作用域能力记忆及未知执行结果不自动重试的规则保持不变。

新增回归以临时模型 HTTP 服务验证默认/自定义提示、请求字段、辅助对象与正确对象交错、无效字段和缺失字段；真实 Scratchpad 磁盘回归验证两轮对话、刷新后回答和原输入保留、丢弃对象不能触发归档，以及仅一次能力协商后后续直接使用兼容调用。未调用外部模型、未重启正在运行的工作区服务，最新真实失败仍需加载新构建后显式重试。

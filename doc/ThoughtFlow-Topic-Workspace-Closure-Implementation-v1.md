## 范围

按用户本轮确认，不承担历史数据、历史 profile 和旧客户端的兼容或自动升级。已有内容的**显式迁移**、新布局中的删除恢复、导入恢复和不可变版本保护仍属于本轮，不能以“不兼容历史数据”为由省略。

本轮实现 P0–P4：文档集编排、稳定位置登记、专题物理存储、显式迁移、资源绑定、检索策略、连续阅读、交付/备份、导入、事件与启动恢复。依赖图、跨文档一致性证明、专题发布基线、多用户权限、远程同步仍按设计属于后续范围。

没有操作用户实际工作区的数据，没有重启用户已有服务；全部自动化数据存放于测试临时目录。本记录不把实现方本地验证视为独立评审或跨平台 CI 的替代。

## 使用说明

1. 从专题列表创建“文档集”。“聚合”保留原有聚合行为；两种模式之间必须先预览再确认转换。文档集不会自动编织成员正文。
2. 在“管理”中建立分组、必需/可选条目和交付级别。可以先建计划项，再选择 profile 创建独立草稿；草稿实际位于 `topics/<topic-id>/thoughts/`，版本链位于同专题的 `documents/`。
3. 填已有 thought ID 是**加入引用**，不会移动原件。物理归拢必须走迁移预览与确认；预览显示路径、文件、空间及迁移前后有效检索策略。取消预览不改变内容或策略。
4. 每篇原件只有一个 owner 和一个可编辑位置。其他专题可以引用同一原件，或复制选定定稿的只读快照。快照复制允许的资源，不复制私有 evidence。
5. “查看定稿”和“查看草稿”独立。没有定稿会明确报不可用；已有定稿加新草稿会同时显示。固定定稿不会随新定稿漂移。专题搜索返回工作版本，并携带被索引 revision，打开时保留专题上下文。
6. 移除条目只解除编目。所属文件仍可在“未编目所属文档”中找回；恢复已删除文档保留原 ID 和版本链，并检查位置冲突。开启公开访问时，显式恢复也会使原公开链接重新可用，界面会提前说明。
7. 专题默认和 thought 的 `inherit/include/exclude` 只控制**全局检索参与**。它们不是访问权限，也不会关闭已有公开链接。非 owner 专题不能改变原件的继承值。
8. `resource://<resource-id>` 只能在正确文档/快照上下文中读取。允许 PNG、JPEG、GIF、WebP、PDF、UTF-8 文本和 Markdown，单文件最多 32 MiB；扩展名与实际类型必须一致，不接收 SVG/HTML/可执行文件。
9. 交付包包含固定选中的定稿、Markdown/HTML 目录及正文和允许的附件，可以离线阅读。完整备份另含所属文档的工作版本、版本链、位置与目录事实；私有证据默认排除，必须显式勾选。清单说明私有证据缺失与离线复核能力的边界。
10. 专题列表支持直接导入备份，空工作区不需要先建同名专题。ID 冲突默认拒绝；导入未完成时不会进入正常列表、检索和定稿。活动/恢复入口显示进行中操作；导入状态接口返回逐对象状态，同 operation ID 可继续恢复。
11. 删除专题只接受空专题和匹配的 topic/catalog generation。所属对象、引用快照、附件或其他保留文件仍存在时拒绝删除；不会递归清空专题目录。

迁移的 staging 和退役源保存在私有恢复目录；完成满七天后在下次启动恢复时清理这些副本，操作记录保留。共享附件原位置保留，避免破坏其他引用。位置记录丢失后的显式重建会保守设为全局排除，需重新确认策略，避免从陈旧快照放开可见性。

## 布局与运行边界

新内容布局版本为 `1`，最低 writer 协议版本为 `1`，由 `.content-registry/schema.json` 声明。受支持入口先持有 OS writer lock，执行布局检查、迁移/导入/恢复与目录对账，再开放正常服务。当前文件系统实现和验证目标是 Linux/macOS，未增加 Windows 存储实现。

不支持把不认识此布局的旧二进制直接覆盖回来运行。若需回退，应停止写入并保留完整工作区备份，在可识别该布局的版本中恢复或显式迁出，验证后再切换程序。本轮没有提供历史二进制兼容承诺。

迁移的私有 staging 复制不持有 namespace/object 锁；提交阶段重新核对来源 generation、完整文件集合、资源绑定和预览中的有效策略，以 rename 发布并退役原件。导出冻结和迁移提交校验仍持有 namespace 写锁；它们不在锁内调用远程模型。大包哈希校验或导出本地 I/O 可能暂时阻塞其他写操作。包限制为 512 MiB、5000 文件、路径深度 16；单资源 32 MiB。对动态磁盘耗尽、真实断电、所有文件系统及浏览器组合的穷举不作已验证声明。

私有 outbox 记录本地操作事实，不是远端消息系统；启动重建与消费当前 generation 是恢复兜底。Git 是本地提交，向量召回是当前服务已支持的路径，均不据此宣称多端同步、HTTP 语义搜索新入口或专题发布基线已实现。
